# 回答の書き方

このディレクトリの `*.md`（この README を除く）が回答です。ファイルの分け方は自由ですが、
いまはカテゴリごとに `01-basics.md` 〜 `20-foundations.md` と分けています（差分が読みやすいため）。

質問そのものは `../questions.tsv` にあり、ここには書きません。見出しの番号で結び付けます。

```markdown
## 1-7

1 BTC は 1 億 satoshi です。satoshi（sat）はビットコインの最小単位です。

<!-- more -->

ブロックチェーン上の金額はすべて satoshi の整数で記録されていて、
「0.5 BTC」は 50,000,000 sat のことです。

関連: 1-12, 1-13
出典: https://github.com/bitcoin/bitcoin/blob/master/src/consensus/amount.h
更新: 2026-09-26
タグ: 安定
```

- `## <番号>` から次の `## ` までが 1 問分です。番号は `questions.tsv` と同じもの
- 空行で段落を分けます。段落の中の改行はそのまま表示されるので、`- ` の箇条書きも使えます
- **本文は Markdown として描画されません。** `` ` `` や `**` を書くと記号のまま画面に出るので使わないでください（テストで検出します）。強調したい語は「」で囲みます
- `<!-- more -->` より上が最初に見える答え、下が「もっと詳しく」です（無くても構いません）
- `関連:` は画面に質問へのリンクとして出ます。存在しない番号を書くと起動に失敗します
- `出典:` は 1 行に 1 つ。何行でも書けます
- `更新:` はその答えの事実を最後に確かめた日です。半減期のように時期で変わる答えには必ず書きます
- `タグ:` は答えの性質です。`・` か `,` で区切って複数書けます。次のタグは画面に注記として出ます

  | タグ | 画面の注記 |
  | --- | --- |
  | `時点依存` | 時期によって変わる情報です。 |
  | `研究提案` | 提案・研究の段階の内容で、いまのBitcoinのルールではありません。 |
  | `実装依存` | ソフトウェアやそのバージョンによって変わります。 |
  | `法域依存` | 国や地域によって答えが変わります。 |
  | `要一次確認` | 最新の一次資料での確認をおすすめします。 |

  それ以外（`安定`、`誤前提`、`概念`、`セキュリティ` など）は管理用で、画面には出ません。
  質問者に「前提が間違っています」と札を貼っても得るものがないからです

## 初心者向けの質問の書き方

基礎知識の棚（1-）や「〇〇とは何ですか？」のような入門的な質問は、読む人がビットコインを初めて知る人だと考えて書きます。

- `<!-- more -->` より上（最初に見える答え）は、専門用語をなるべく使わず、日常の言葉とたとえで説明します。専門用語を使うときは、その場で短く言い換えます（例：「ノード（ネットワークに参加しているコンピューター）」）
- 正確さのための技術的な説明（UTXO、コンセンサスルールなど）は `<!-- more -->` の下に置きます。技術者向けの質問だと判定されたときは、この部分が最初から開いた状態で表示されます
- 答えの中に出てくる専門用語には、それ自体を説明する質問（「〇〇とは何ですか？」）を用意し、`関連:` でつなぎます。用語の質問は用語集として別の棚にまとめず、その用語が属する棚に置きます（例：ビザンチン将軍問題は 20-、ノードは 6-）。棚の説明（`categories.json` の `what`）にも用語名を書き足します

新しい質問の番号は、その棚の「いちばん大きい番号 + 1」にします。欠番（削除した質問の番号）は再利用しません。

回答が無い質問も判定の対象です。当たった場合は「回答を準備中です」と表示されます。
