# jev-mystery

自由入力の推理ゲームです。プレイヤーは選択肢を見ません。何をしたいかを文章で書き、
それが**その場でできることのどれかに十分近ければ**、その行動が起こります。近いものが
なければ、何も起こりません。

最後に全員を集め、誰がどうやってなぜやったのかを**文章で**書きます。その文章が採点され、
エンディングが決まります。

## なぜ Jev なのか

[Jev](https://docs.typesafe.ai/introduction) は文章を生成しません。返ってくるのは
**コードが直接分岐できる型付きの値**だけです。このゲームで Jev がやるのは二つだけで、
どちらも「読んで分類する」仕事です。

| 場面 | 聞き方 | 使い道 |
| --- | --- | --- |
| 入力 → 行動 | `choice`（その場で可能な行動 + `none`） | どの行動を求めているか |
| 入力の種類 | `choice`（移動 / 調査 / 尋問 / 会話 / メタ / 無意味） | 空振りの文面を選び分ける |
| 締めようとしているか | `noul` | 早すぎる名指しに「まだ早い」と返す |
| 最終回答の犯人 | `choice`（容疑者 + `none`） | 名指しが当たっているか |
| 真相の要素ごと | `noul` × 要素数 | どこまで辿り着いたか |
| 論の筋 | `score`（5段階） | 説明として成立しているか |

プレイヤーが読む文章は**すべて人間が書いたもの**で、シナリオの JSON に入っています。
モデルは一行も書きません。

**真相をモデルに渡しても漏れません。** 採点のとき、`state` にはその事件の真相がそのまま
入ります。Jev はテキストを返さないので、真相が player に戻る経路が構造的に存在しません。
チャット型の LLM で同じことをすると、真相をプロンプトに入れた時点で漏洩を抱えます。

## 選択肢は見せない

これはゲームの根幹です。プレイヤーが読むのは、起きたことと、いまいる場所と、手の中の
ものだけ。**何を打てたのかは決してレスポンスに乗りません。**

- シナリオはサーバ側にしかない（バイナリに `go:embed` で埋め込み）
- 行動の一覧も、その説明文も、エンディングも、真相も返さない
- 返るのは、当たった行動の結果の文章と `did`（「机を調べた。」）だけ
- 唯一の無料のヒントは「いま誰がここにいるか」と「そろそろ話がつながりそうだ」の二つ

`internal/server/server_test.go` の `TestResponsesDoNotLeakTheScenario` が、レスポンスの
JSON にシナリオの行動 ID・説明文・真相・エンディングが混じっていないことを毎回確かめます。

## 構成

```
ブラウザ ──POST /api/act──> Cloud Run ──> api.typesafe.ai
  （物語と、いる場所と、       （シナリオと      （入力を分類する）
    手の中のものだけ）          API キーを持つ）
```

| パッケージ | 役割 |
| --- | --- |
| `internal/scenario` | 事件の中身（文章・人・場所・行動・真相）と、その検証 |
| `internal/game` | 何ができるか、何が起きるか、入力をどう行動に落とすか |
| `internal/session` | プレイ状況を署名付きトークンにしてブラウザに預ける |
| `internal/server` | HTTP。ここが「見せてよいもの」の境界 |
| `internal/jev` | System One API のクライアント（`jev-nostr` と同じもの） |

`internal/jev` は jev-nostr からのコピーです。このリポジトリはサービスごとに別モジュールで、
Go は他モジュールの `internal` を import させないため、共有ではなく複製しています。

### 状態はサーバに持たない

Cloud Run はゼロまで縮み、複数インスタンスで動きます。ゲームをメモリに持つと、途中で
消えます。そこで**状態はブラウザに預け、毎ターン往復させます**。中身は秘密ではありません
（どこにいて何を見つけたか＝プレイヤーが読んだこと）が、次に何ができるかを決めてしまうので、
HMAC-SHA256 で署名しています。書き換えたトークンは 400 で弾かれます。

### しきい値は Go 側

Jev には「入力は何か」だけを聞き、「それを採用するか」は Go で決めます
（`game.Policy`）。判定はこうです。

1. 選ばれたのが `none` ではない
2. その確率が `none` の確率より大きい
3. かつ `Match`（既定 0.40）以上で、`confidence` が `Confidence`（既定 0.35）以上

`none` を選択肢として**必ず混ぜる**のが要点です。`choice` の確率は合計 1 なので、受け皿が
ないと無関係な入力が「いちばん似ていない度合いの低い行動」に流れ込みます。

既定値は測定値ではなく出発点です。`MATCH_THRESHOLD` などの環境変数と CLI のフラグで
動かせます。

## 動かす

```sh
export TYPESAFE_API_KEY=...
go run ./cmd/server           # http://localhost:8080
```

ページは `docs/mystery.html`（GitHub Pages）です。ローカルのサーバに向けるには
`?api=http://localhost:8080` を付けます。

| 環境変数 | 既定値 | 内容 |
| --- | --- | --- |
| `TYPESAFE_API_KEY` | （必須） | 無いと起動しない |
| `SCENARIO` | `clockwork` | 埋め込まれた事件の ID |
| `GAME_SECRET` | （毎回ランダム） | 状態トークンの署名鍵。本番では必ず設定する |
| `JEV_MODEL` | `jev-latest` | モデル識別子 |
| `MATCH_THRESHOLD` / `CONFIDENCE_THRESHOLD` / `POINT_THRESHOLD` | 0.40 / 0.35 / 0.50 | しきい値 |
| `GAME_DEBUG` | | `1` でモデルの生の数字をレスポンスに含める（調整用） |
| `TYPESAFE_ENDPOINT` | | 接続先の差し替え（スタブ用） |

### CLI で測る

このゲームの成否は、ほぼ一点にかかっています。**プレイヤーが実際に打つ日本語が、
狙った行動に当たるか。** これは議論ではなく計測の対象なので、計測できるようにしてあります。

```sh
go run ./cmd/cli -script testdata/walkthrough.txt -accuse testdata/solution.txt
```

`walkthrough.txt` は `入力<TAB>当たるべき行動 ID` です（`none` は「何にも当たらないのが
正解」）。実行の最後に何件中何件が狙いどおりだったかが出ます。スクリプトを省くと標準入力を
読むので、ターミナルでそのまま遊べます。

`-v` を付けると、そのターンに何が選択肢として出ていたかも表示されます。

## 事件を書く

`internal/scenario/data/*.json` に置くと、`SCENARIO` で選べるようになります。読み込み時に
検証され、参照の壊れたシナリオはサービスが起動しません。

```json
{
  "id": "...", "title": "...",
  "opening": ["..."], "incident": ["..."],
  "start_scene": "hall",
  "scenes":     [{ "id": "hall", "name": "...", "description": ["..."], "characters": ["..."] }],
  "characters": [{ "id": "...", "name": "...", "role": "...", "avatar": "🗂" }],
  "evidence":   [{ "id": "...", "name": "...", "description": "..." }],
  "actions": [{
    "id": "examine_clock",
    "scenes": ["hall"],
    "requires": { "evidence": ["..."], "flags": ["..."], "not_flags": ["..."] },
    "match": { "what": "...", "not_for": "...", "examples": ["...", "..."] },
    "speaker": "kurata",
    "did": "柱時計を調べた。",
    "result": ["..."], "repeat": ["..."],
    "gives_evidence": ["clock"], "sets_flags": ["..."], "moves_to": "study"
  }],
  "misses": { "default": ["..."], "move": ["..."], "ask": ["..."], "declare": ["..."] },
  "finale": { "...": "..." }
}
```

書くときのコツは三つです。

1. **`match` は排他的に書く。** `choice` の確率は合計 1 なので、「書斎を調べる」と
   「書斎の机を調べる」が並ぶと票が割れて共倒れします。紛らわしい組には `not_for` を
   必ず入れてください。`what` だけをいくら足しても分かれません。
2. **難易度は `requires` で作る。** 条件を満たさない行動はそもそも Jev に見せないので、
   「まだできない」は自動的に「何も起こらない」になります。
3. **空振りの文章を手を抜かずに書く。** 序盤にプレイヤーがいちばん多く読むのは空振りです。
   だから `misses` は intent ごとに分かれています。

`finale.points` は真相の要素ひとつにつき `noul` ひとつ。まとめて「合っているか」を聞かない
のは、**犯人を当てた人とトリックまで見抜いた人の差がエンディングを決める**からで、単一の
判定にはその差が乗りません。8 問聞いても並列に評価されるのでコストはほとんど変わりません。

`endings` は上から順に判定し、最初に条件を満たしたものが採用されます。最後の一つは無条件で
なければならず、そうでなければ読み込み時に落ちます。

## まだ無いもの

- **レート制限がありません。** 1 ターン = 有料 API 1 リクエストです。公開して遊ばせるなら
  Cloud Run の同時実行数だけでは足りません。
- **事件が 1 本だけで、それも動作確認用のプレースホルダです。** エンジンを端から端まで
  動かすために書いたもので、謎解きとしての出来は測っていません。
- **日本語での当たり方が未測定です。** 質問文は英語、選択肢の説明とプレイヤーの入力は
  日本語という組み合わせで書いてあります。上の CLI を CI から回すのが、それを測る唯一の手です。
